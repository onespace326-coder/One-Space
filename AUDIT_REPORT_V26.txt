ONESPACE V26 — STATIC AUDIT REPORT
==================================
Audit target: OneSpace_V25_Aries_Email_Task_Hardening.zip
Audit date: 06 November 2026
Scope: Supplied project source only; no Supabase/Gmail credentials or remote
production access were used for live tests.

RESULT
------
Static source validation: PASS
Live integrations: NOT VERIFIED (requires deployment and signed-in test account)
Google backend audit: BLOCKED (server-side Google function folders absent)

CHECKS EXECUTED
---------------
- Node syntax check passed for every root-level .js file.
- Node syntax check passed for all 13 inline <script> blocks in index.html.
- Included Aries Edge Function passed a TypeScript no-emit check using local
  declarations for Deno and the remote Supabase module (Deno CLI/runtime itself
  was not available, so this is not a Deno deployment test).
- All relative script and link references found in index.html resolve to files
  inside the supplied project folder.
- Root V23 PREPARE SQL matches its copy in supabase/migrations/.
- Root V23 ENFORCE SQL matches its copy in supabase/migrations/.
- Browser auth-config.js has no detected service_role or sb_secret key value.
- Final ZIP archive integrity checked with unzip -t.
- Repeatable validation script included: onespace-v27-verify.mjs.

REPAIRS APPLIED
---------------
- Added missing publishable `apikey` headers to direct Google Edge Function
  fetches in sync, status, OAuth-start and attachment flows. Supabase documents
  that direct Edge Function calls use the user JWT in Authorization and the
  project publishable key in apikey.
- Gmail composer scope matching now recognises the broad mail.google.com scope.
- Both Google sync entry points require a confirmed successful account sync
  before reporting success.
- Gmail endpoint probes reliably clear timeouts and report connectivity
  separately from authenticated operation success.
- Scheduled-task form prevents repeated submissions during pending RPC calls,
  catches thrown network errors, and requires a created task ID before success.
- Background Google auto-sync uses safe interval parsing and bounds.
- Aries context prompt-injection exposure reduced by moving workspace JSON out
  of the system prompt and labelling it untrusted; language prompt values are
  allow-listed; malformed input/configuration and upstream timeout are handled.
- Aries now prefers the current SUPABASE_PUBLISHABLE_KEYS environment map and
  falls back to SUPABASE_ANON_KEY while Supabase's legacy/new key transition is
  in progress.
- Service-worker cache version advanced from V25 to V26.

MISSING SOURCE / BLOCKERS
------------------------
The package includes only supabase/functions/aries-chat/index.ts. The following
server-side functions referenced by the browser or prior deployment notes are
not present: google-oauth-start, google-oauth-callback,
google-integration-status, google-sync, google-send-OneSpace,
google-mail-action-OneSpace, google-mail-attachment, aries-approve-reply,
aries-email-scan, and aries-health. Therefore token-vault use, refresh-token
handling, OAuth redirect allow-list, per-user account checks, Google scopes,
Gmail mutation action mapping, server-side input validation and CORS cannot be
certified or repaired from this ZIP.

The scheduled-task execution worker and Cron configuration are not included.
The V23 SQL migration files are available, but this static audit did not execute
them against the live Supabase database or verify existing RLS policies.

SECURITY NOTE
-------------
The Supabase publishable key in auth-config.js is intended for browser use and
is not a service-role secret. Never place sb_secret_* keys, service_role keys,
Anthropic API keys, Google OAuth client secrets, or refresh tokens in the
GitHub Pages repository.
